# LUT-001

Address lookup tables are a **cache and provenance** problem, not a
reason to hand-grow `configs/luts/warm.jsonl`.

Research: the old control plane called `getAddressLookupTable` as
JSON-RPC (21,410 attempts, 0 successes). The RPC path is
`getAccountInfo` plus account deserialize. A receipt-ordered sparse
learner resolved 66,958 / 74,554 (89.81%) of eligible raw-before-executed
txs; those address sets matched executed bytes. Provider pre-resolved
lists are not trusted (9 finalized discrepancies). Canonical v0 order is
already in `txview_resolve`: all writable LUT addresses, then all
readonly, descriptor order, **without** deduplicating repeated table
descriptors.

```text
STATIC warm  +  sparse (table, index) → addr  +  off-path full-table fetch
        ↓
  txview_resolve_at / pumpstate_from_cache
        ↓
  miss → do not apply
```

A LUT miss is not a global fatal. The tx is not applied. If a **static**
key of that message is an armed pool, that pool goes DIRTY (continuity
uncertain) until re-anchor. Unknown pools named only inside the missing
table are not guessed.

Off-path:

```text
python tools/lut/learn.py --loop run/lut_miss.jsonl run/lut_learned.jsonl
```

uses `getAccountInfo` only. Account bytes: addresses start at offset 56
(LOOKUP_TABLE_META_SIZE in web3.js / Agave, which already includes the
u32 ProgramState). Offset 60 drops the first address bytes and fails
alignment. After a learned table is installed, its miss-queue slot is
dropped so new tables can be fetched. Full-table capacity remains
`WIRE_LUT_MAX`; overflow tables install as sparse entries.
`live_state_001 --lut-miss … --lut-learned …`
flushes misses and reloads learned tables each second.

Lifecycle (when meta is present): indices `>= start_index` are unusable
in `last_extended_slot`; deactivated tables fail closed after
`deactivation_slot`. Warm jsonl without meta is an uncertified address
fact.

Do not treat a provider's loaded-address vector as ground truth.
